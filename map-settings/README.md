# map-settings — чтение, инспектирование и редактирование настроек МАП через UI

Новый модуль sunReceiver для работы с **параметрами (ячейками) настроек МАП**
(Титанатор / Доминатор): чтение, инспектирование и редактирование через веб-UI
встроенного дашборда. В отличие от `mapgateway` (шлюз Modbus TCP ↔ RTU) и
`modbusmap` (только чтение блоков для телеметрии), этот модуль даёт **оператору**
доступ к полному набору ячеек МАП с русскими именами, единицами и границами, и
позволяет безопасно изменять их значения.

> **Статус:** модуль реализован (первая версия). Страница дашборда `/map-settings`,
> API `/api/map-settings*`, каталог ячеек `mapsettings/catalog.json` (сгенерирован
> из документа генератором `mapsettings/catalog_gen.py` и встроен в бинарник).
> Чтение и запись — по **Modbus TCP через `mapgateway`** (порт 502 на ПАК
> «Малина»).
>
> **Источник истины — только последняя версия документации:**
> `docs/map/map/protocol_MAP_cells_2026_07_15.doc` (каталог `docs/map/`
> локальный, в git не выгружается). **Malina web API подсматривать можно, но
> реализовывать исключительно по последнему документу**: веб-API ПАК «Малина»
> очень старый и делался по устаревшей документации, поэтому его как эталон
> использовать нельзя.

## Требования (зафиксированы)

1. **Две кнопки в UI: «Перечитать» и «Записать».** Других действий оператора нет;
   вся служебная обвязка (бэкап, валидация, верификация, журнал) — внутри.
2. **Считываются и отображаются все параметры.** «Перечитать» снимает полный
   снимок настроечных ячеек МАП (для выбранного режима) и показывает их в UI.
   Ничего не скрывается.
3. **Записываются только изменённые пользователем параметры.** «Записать»
   отправляет на МАП **исключительно** те ячейки, чьё значение в UI отличается от
   прочитанного; нетронутые ячейки не пишутся вообще.
4. **Все параметры названы по-русски и объединены в логические блоки.** Имена без
   латиницы/аббревиатур без расшифровки; группировка по смыслу (АКБ, сеть,
   генерация, инвертор, часы/сервис и т. п.).
5. **Команды записи обрамляются служебными кодами, как это делает `mapd`:**
   `03` (write-enable) → запись ячейки(ек) → `07` (`ComMAP_Call_load_EEProm`).
   Без этого обрамления запись в EEPROM/RAM МАП не применяется (см. ниже).
6. **Источник истины — последний документ** (`protocol_MAP_cells_2026_07_15.doc`).
   Malina web API — только для подсматривания, не эталон (он по устаревшей
   документации).
7. **Два режима устройства: Титанатор и Доминатор.** От режима зависит набор
   отображаемых параметров и другие особенности. Последний использованный режим
   **сохраняется на клиенте** и восстанавливается при следующем открытии.
8. **IP и порт МАП редактируются и сохраняются на клиенте.** Адрес/порт — часть
   клиентских настроек (не хардкод), переживают перезапуск.
9. **Текущее время — отдельная форма редактирования**, не входит в общую
   страницу настроек (там его нет).
10. **Отдельный раздел для управляющих воздействий** (действия, а не изменение
    параметров). В этом же разделе отображаются **все параметры МАП, не являющиеся
    настройками**: состояния, параметры сети и т. п. Всё — в логически
    обоснованном виде (см. раздел ниже).

## Режимы устройства: Титанатор и Доминатор

Модуль поддерживает **два режима** МАП, переключаемых оператором:

- **Титанатор** — свой набор параметров и особенностей;
- **Доминатор** — свой набор (пересечение частичное, часть ячеек/групп отличается).

Режим определяет:
- **набор отображаемых параметров** и состав логических блоков;
- особенности чтения/записи соответствующих ячеек.

Последний использованный режим **сохраняется на клиенте** (браузерное хранилище)
и **восстанавливается при запуске** страницы, чтобы оператор не выбирал его
каждый раз. Выбор режима — часть клиентских настроек (см. ниже). Наборы
параметров для обоих режимов строятся из одной актуальной документации
`protocol_MAP_cells_2026_07_15.doc` (модели Pro/Hybrid/Dominator/Титанатор).

## Клиентские настройки (режим, IP, порт)

Параметры подключения и режим хранятся **на клиенте** (localStorage браузера) и
восстанавливаются при открытии страницы:

| Настройка | Назначение | По умолчанию |
|---|---|---|
| Режим | `Титанатор` / `Доминатор` — определяет набор параметров | последний сохранённый |
| IP | адрес МАП (или `mapgateway`) | последний сохранённый |
| Порт | Modbus TCP порт МАП | последний сохранённый (502) |

Клиентские настройки передаются в API при чтении/записи; сервер не требует
отдельного конфиг-раздела для адреса (можно иметь дефолт из `map.rs485`).
«Сохранить на клиенте» происходит при изменении соответствующего поля.

## Форма «Текущее время»

Установка времени МАП — **отдельная форма**, вне общей страницы настроек
(пункт 9 требований). Оператор вводит дату/время, форма пишет нужные ячейки
(`0x1B6 _LCD_TimeCyr` = `(hh<<3)|(mm/10)` и `0x44B _TimeCyr_MINUT` = `mm%10`)
тем же обрамлённым протоколом (`03 → запись → 07`). Точная семантика и состав
ячеек — по `protocol_MAP_cells_2026_07_15.doc`; имя ячейки времени в старой
документации (`_LCD_TimeCyr`) сверять с актуальной. Форма не смешивается с
таблицей параметров.

## Управляющие воздействия и мониторинг (отдельный раздел)

Помимо редактирования настроек, у МАП есть **действия** (управляющие воздействия)
и **не‑настроечные параметры** (состояния, телеметрия). И то, и другое выносится в
**отдельный раздел**, отделённый от таблицы настроек. Внутри раздела — две
логические части.

### 1. Управляющие воздействия (действия)

Это **не** изменение параметров, а команды/процедуры, выполняемые на МАП
(например, фиксация EEPROM `07 ComMAP_Call_load_EEProm`, сброс ошибок/аварий,
перезапуск, сервисные операции). Состав действий и их служебные коды — **строго
по последней документации** (`protocol_MAP_cells_2026_07_15.doc`), с той же
обвязкой, что и запись: подтверждение, бэкап при необходимости, чтение-обратно и
журнал. Каждое действие описывается дескриптором:

```go
type mapAction struct {
    Key     string // стабильный идентификатор для UI/API
    Name    string // русское имя (обязательно)
    Group   string // логический блок
    Desc    string // что делает (по-русски)
    Modes   []string // для каких режимов доступно
    Confirm bool   // требует ли подтверждения
    Codes   []byte // служебные коды/последовательность команд (из документа)
}
```

Действия, разрушительные или меняющие режим работы, выполняются только после
подтверждения; опасные — с бэкапом.

### 2. Не‑настроечные параметры (только чтение)

Отображаются **все параметры МАП, не являющиеся настройками**: состояния,
режим, аварии, параметры сети, батареи, выхода, счётчики и т. п. Они не
редактируются (в снимке настроек им соответствует класс `readonly`), но должны
быть видны в этом разделе. Раскладка — логически по подсистемам:

| Логический блок | Что показывает |
|---|---|
| **Состояние и режим МАП** | текущий режим/состояние, статусные флаги, аварии и ошибки |
| **Сеть** | напряжение, частота, ток, мощность, направление переток |
| **Батарея (АКБ)** | напряжение, ток заряда/разряда, температура, SOC |
| **Выход / инвертор** | напряжение, ток, мощность, генерация |
| **Энергия и счётчики** | накопленная энергия, счётчики, часы работы |
| **MPPT / панели** | параметры контроллеров и панелей (если применимо) |
| **Служебное** | версия ПО, серийный номер, температура, время |

Порядок и состав блоков зависят от выбранного режима (Титанатор/Доминатор) и
уточняются по актуальной документации. Значения только читаются; кнопки
«Перечитать»/«Записать» к ним не применяются (перечитать — да, записать — нет).

## Назначение и границы

Модуль решает три задачи:

1. **Чтение** — снять с МАП актуальный снимок всех настроечных ячеек по Modbus TCP.
2. **Инспектирование** — показать ячейки в UI по логическим блокам, с русским
   именем, значением, единицей, границами и пометкой «изменено пользователем».
3. **Редактирование** — применить только правки оператора, с проверкой
   допустимости, бэкапом, служебным обрамлением и чтением-обратно (верификацией).

Что модуль **не** делает:

- не трогает прошивку (это `map-loader/` и `MAP2Gui_`) и не переводит МАП в режим
  загрузчика;
- не заменяет телеметрию (`mppt_api.go`, `runMapPoll`) — поток данных на дашборд
  остаётся прежним;
- не управляет инверторами/реле.

## Кросс-платформенность

Требование: модуль должен одинаково работать на Linux (прод `192.168.13.253`,
amd64), macOS (разработка) и Windows (portable-сборка). Это достигается так:

- **Только Go, `CGO_ENABLED=0`.** Никаких C-зависимостей и COM-портов: RS485
  МАП уже доступен как **Modbus TCP** через `mapgateway` (`:502`), а не через
  локальный `/dev/ttyUSB*`. Прямой USB-UART (FTDI) в модуль не зашивается.
- **Один сетевой транспорт** — `net.DialTimeout("tcp", ...)`, одинаков на всех ОС.
- **UI эмбеддится в бинарник** через `//go:embed web` (как дашборд, см.
  `web.go`): отдельные файлы на диске не нужны ни на одной платформе.
- **Сборка** — существующими целями `Makefile` (`linux-x64`, `win-x64`, плюс
  нативная macOS-сборка), без платформенных тегов и без `-H windowsgui`-специфики.
- Платформенных файлов (`*_windows.go` / `*_posix.go`) модуль не требует, кроме
  уже существующих логгеров/трея.

## Архитектура

```
браузер (страница «Настройки МАП» в дашборде)
        │  HTTP/JSON, Basic-auth (как /api/* дашборда)
        ▼
map_settings_api.go  ── HTTP-обработчики: снимок, применение правок
        │
        ▼
map_settings.go      ── реестр параметров + валидация + backup/verify
        │
        ▼
modbusmap (расширение) ── чтение 0x03 и запись 0x06 (со служебными кодами)
        │
        ▼
mapgateway (:502) ── Modbus TCP → Modbus RTU (USB) ──► МАП (Титанатор/Доминатор)
```

Модуль переиспользует имеющееся:

- **`modbusmap.Client`** — адресация «слово = 2 байт-ячейки МАП» уже
  реализована в `modbusmap/client.go` (`ReadRegisters`). Добавить `WriteRegister`
  (функция `0x06`) с той же побайтовой упаковкой ячеек. `mapgateway` уже умеет
  `0x03/0x06/0x10` (см. `mapgateway/README.md`).
- **Дашборд и авторизация** — новый API-маршрут вешается на `buildDashboardMux`
  (`dashboard.go`) под той же Basic-auth (`dashboard_user`/`dashboard_password`),
  новая страница — в `web/templates/` рядом с `index/charts/energy/bms`.
- **Redis/PG** — для отображения не нужны: настройки читаются с устройства по
  запросу. Бэкапы/аудит (см. ниже) при необходимости хранятся в Redis/PG.

### Разделяемый доступ к шине

`modbusmap.Client` рассчитан на **одного** последовательного пользователя, а
реестр МАП медленный (первый ответ — десятки секунд, блокирующие чтения по 3 с).
Поэтому настройки читаются/пишутся **независимым соединением**, и на время
«Записать» пулер телеметрии приостанавливается (или берётся общий мьютекс шины).
Это нужно решить на этапе реализации (см. «Открытые вопросы»).

## Реестр параметров (каталог ячеек)

Основа — `protocol_MAP_cells_2026_07_15.doc` (последняя версия): RAM и EEPROM
ячейки с адресами, масштабами и допустимыми значениями. Каждый параметр
описывается дескриптором:

```go
type mapParam struct {
    Key      string  // стабильный идентификатор для UI/API
    Cell     uint16  // адрес байт-ячейки МАП
    Wid      int     // ширина: 1/2/4 байта (склейка старших/младших ячеек)
    Name     string  // русское имя (обязательно)
    Group    string  // логический блок: «АКБ», «Сеть», «Генерация», «Часы»
    Modes    []string // для каких режимов актуален: «Титанатор»/«Доминатор»
    Unit     string  // В, А, °C, ...
    Scale    float64 // множитель отображения
    Min, Max float64 // допустимый диапазон
    Kind     paramKind // RAM (runtime) | EEPROM (настройка) | readonly
    Write    bool    // доступно ли редактирование
    Enum     map[int]string // расшифровка перечислимых значений (по-русски)
}
```

Каталог — данные, а не разбросанная логика: таблица дескрипторов (встроенный
JSON, сгенерированный из `.doc`), чтобы добавление ячейки не требовало правки
кода. **Каждый параметр обязан иметь русское `Name` и `Group`** — параметров без
имени/блока в UI быть не должно. Поле `Modes` задаёт принадлежность режиму:
набор отображаемых параметров зависит от выбранного режима (Титанатор/Доминатор),
поэтому один и тот же `Cell` может встречаться в разных наборах.

### Классы ячеек

- **readonly (телеметрия)** — показываются в снимке, не редактируются.
- **RAM** — рантайм-параметры; меняются до перезагрузки.
- **EEPROM** — сохраняемые настройки; запись требует служебного обрамления и
  бэкапа.

## Протокол записи (служебные коды, как у `mapd`)

Ключевое требование. `mapd` не пишет ячейку «в лоб»: запись в МАП **обрамляется**
служебными командами. По трассировке COM-порта `mapd` (`plans/malina-upgrade.md`,
2026‑09‑25): команда `03` (write-enable) → запись ячейки → `07`
(`ComMAP_Call_load_EEProm`), после чего `mapd` перечитывает страницу `0x0100`
(обновляя shm `0x1B6`) и сбрасывает `0x403`. Сама страница `0x0100` не шлёт.

В терминах Modbus TCP (канал `mapgateway :502`, unit 1, побайтовая адресация,
делить на 2 не нужно; `mapgateway` пропускает `0x06`) последовательность записи:

1. **Разрешение записи:** функция `0x06`, адрес `0x0000` = `0x0003`
   (`ComMAP_EEPromWR` — разрешение записи в EEPROM/RAM).
2. **Запись значений:** функция `0x06` для каждой изменённой ячейки
   (`0x06 addr value`).
3. **Фиксация:** команда `07` (`ComMAP_Call_load_EEProm`) — завершение/загрузка
   EEPROM. Именно это «закрывает» обрамление.

Деталь точного представления команды `07` в Modbus-канале (отдельный регистр/ячейка
или запись в управляющую ячейку `0x0000`) уточняется на этапе реализации по
`protocol_MAP_cells_2026_07_15.doc` и контрольному чтению. До подтверждения
`07`-эквивалент в коде не «угадывать», а проверять на живом МАП read-back-ом.

Дополнительно, как `mapd`:

- после записи — **перечитать** затронутые ячейки (страницу) и сбросить `0x403`;
- не полагаться на shm/веб-кэш Малины: верификация — только по свежему чтению
  из МАП (shm `0x1B6` обновляется лишь при записи `0x1B6` и в обычном цикле
  «заморожен»).

## UI

Новая страница дашборда (`/map-settings`, заголовок «Настройки МАП»):

- вверху — **выбор режима** (`Титанатор` / `Доминатор`), поля **IP** и **порт**
  МАП; значения сохраняются на клиенте и восстанавливаются при открытии;
- **логические блоки** (секции/аккордеоны) с русскими названиями; внутри —
  таблица параметров, актуальных для выбранного режима, с русскими именами,
  адресом ячейки, значением + единицей, диапазоном и пометкой «изменено»;
- значение редактируется inline; недопустимые значения подсвечиваются по
  `Min/Max`/`Enum`;
- внизу — **две кнопки: «Перечитать»** (полный снимок заново, сброс правок) **и
  «Записать»** (применить только изменённые параметры);
- журнал последней операции (что прочитано/записано, результат) — на странице;
- **«Текущее время» — отдельная форма** (свой маршрут/страница), не входит в
  общую страницу настроек; см. раздел выше;
- **«Управляющие воздействия и мониторинг» — отдельный раздел** (свой
  маршрут/вкладка): действия с МАП и все не‑настроечные (read-only) параметры,
  сгруппированные логически; см. раздел выше;
- на мобильных — та же адаптивная раскладка, что у остального дашборда.

Структура разделов страницы «Настройки МАП»:

1. **Настройки** — редактируемые параметры по логическим блокам, кнопки
   «Перечитать» / «Записать».
2. **Управляющие воздействия и мониторинг** — отдельный раздел: действия + все
   не‑настроечные параметры (состояния, сеть, АКБ, выход, счётчики, служебное).
3. **Текущее время** — отдельная форма.

## API (черновик)

| Метод и путь | Назначение |
|---|---|
| `GET /api/map-settings?mode=&ip=&port=` | снимок **всех** параметров выбранного режима: `settings` (rw) + `monitor` (ro) + `actions` + `errors` |
| `POST /api/map-settings/apply` | записать **только изменённые** настройки: валидация → обрамлённая запись → read-back; в теле — режим, адрес и пары `{key: value}` правок |
| `POST /api/map-settings/action` | управляющее воздействие: `{key}` действия (+ режим/адрес); подтверждение и служебные коды — из дескриптора |
| `GET /api/map-settings/time?mode=&ip=&port=` | прочитать текущее время МАП (ячейки `0x1B6`/`0x44B`) |
| `POST /api/map-settings/time` | записать время МАП `{hour, minute}` тем же обрамлённым протоколом |

Тело `apply` содержит лишь правки оператора; сервер сам определяет изменённые
ячейки, применяет служебное обрамление и возвращает по каждому параметру итог
(принято/ошибка) и фактическое значение после верификации. Адрес МАП (IP/порт) и
режим приходят с клиента. Все ответы — JSON.

## Безопасность и целостность

1. **Пишем только изменённое.** `apply` вычисляет дельту сама: параметры, равные
   прочитанному снимку, на МАП не уходят.
2. **Бэкап до записи.** Полный снимок редактируемых ячеек сохраняется (метка
   времени + оператор) до любой записи, чтобы откатиться.
3. **Валидация.** Каждое значение проверяется по `Min/Max`, `Enum` и ширине
   ячейки; для EEPROM — явные границы.
4. **Служебное обрамление обязательно.** Любая запись — только через
   `03 (write-enable) → запись → 07 (load EEPROM)`; «сырая» запись запрещена.
5. **Чтение-обратно (verify).** После записи ячейки перечитываются; расхождение —
   ошибка в журнале, а не тихий успех.
6. **Аудит.** Время, пользователь, параметр, было → стало, результат.
7. **Доступ.** Страница и API — под Basic-auth дашборда.
8. **Только параметры из реестра.** Никаких записей «по адресу» без дескриптора.

## Конфигурация

Адрес МАП и режим задаются **на клиенте** (см. «Клиентские настройки»);
серверный конфиг используется только как дефолт — **`map.rs485`** (`ip`, `unit`).
Если понадобится выключатель — добавить **обязательное** поле
`map.settings_disabled` (`false` — модуль активен, `true` — страница и API
скрыты) и синхронно обновить `sunReceiver.sample.json` и `docs/README.md`
(правило проекта: sample всегда актуален).

## Сборка и релизы

Отдельных артефактов нет — модуль часть основного бинарника. Собирается теми же
целями `Makefile` (`linux-x64`, `win-x64`, нативная macOS), `CGO_ENABLED=0`,
статически; UI эмбеддится. Деплой — общий (`docs/README.md`, раздел «Деплой»).

## Реализация (фактическая)

| Что | Где |
|---|---|
| Ядро модуля (реестр, чтение снимка, дельта-запись, действия, время) | `mapsettings.go` |
| HTTP API + страница | `mapsettings_api.go` |
| Каталог ячеек (JSON, встроен через `go:embed`) | `mapsettings/catalog.json` |
| Генератор каталога из `.doc` | `mapsettings/catalog_gen.py` |
| Запись в Modbus-клиенте (0x06/0x10, команды) | `modbusmap/write.go` |
| Шаблон страницы / стили / скрипт | `web/templates/mapsettings.html`, `web/static/css/mapsettings.css`, `web/static/js/mapsettings.js` |
| Регистрация в дашборде (страница + API + навигация) | `dashboard.go`, `web.go`, `web/templates/base.html`, `main.go` |

Особенности реализации:

- **Транспорт** — `modbusmap.Client` к `mapgateway` (`<ip>:502`), функция 0x03
  (чтение) и 0x06 (запись байта) + служебные команды.
- **Снимок** читается блоками: соседние адреса (зазор ≤ 16 байт) объединяются,
  блок ≤ 240 байт (лимит 120 слов); частичный сбой блока не отменяет остальные
  (ошибки возвращаются в `errors`).
- **Запись** — только изменённые параметры; обрамление
  `ComMAP_EEPromWR(3) → WriteCell… → ComMAP_Call_load_EEProm(7)` + чтение-обратно.
- **Кнопка «?»** есть у каждого параметра (настройки и мониторинг) и у каждого
  органа управления; по нажатию показывается подсказка из документации (описание,
  единица/формула, расшифровка значений и битов).
- **Клиентские настройки** (модель, IP, порт) — в `localStorage` браузера,
  подставляются в запросы; серверный конфиг — только значения по умолчанию.
- **Навигация**: пункт «Настройки МАП» появляется, когда `map` включён и задан
  `map.rs485.ip`.

## Открытые вопросы для реализации

1. **Сосуществование с пулером телеметрии.** Отдельное соединение + пауза
   `runMapPoll` на время записи vs. общий мьютекс шины.
2. **Точное представление команды `07` (`ComMAP_Call_load_EEProm`)** в
   Modbus-канале — подтвердить по справочнику и живым read-back.
3. **Различие режимов Титанатор/Доминатор.** Сверить по
   `protocol_MAP_cells_2026_07_15.doc` полный состав ячеек, пересечение и
   отличия; откуда брать признак текущего режима устройства (автоопределение или
   только ручной выбор оператором).
4. **Хранение бэкапов и аудита.** Redis (живёт 2 суток) или PG (история) —
   выбрать, чтобы бэкапы не терялись при очистке Redis.
5. **Источник каталога ячеек.** Генерировать реестр из `.doc` офлайн и
   коммитить как встроенный JSON, или вести таблицу в коде.
6. **Разбиение на логические блоки** — согласовать финальный список русских
   названий групп и параметров.
7. **Форма времени.** Точная семантика и состав ячеек времени по последнему
   документу (в старой документации `_LCD_TimeCyr`/`_TimeCyr_MINUT`).
8. **Клиентское хранилище.** Ключи localStorage для режима/IP/порта — зафиксировать
   и версионировать (миграция при изменении схемы).
9. **Перечень управляющих воздействий.** Полный список действий и их служебных
   последовательностей — только по `protocol_MAP_cells_2026_07_15.doc`; какие из
   них разрешать из UI и какие требуют подтверждения/бэкапа.
10. **Состав не‑настроечных параметров и логических блоков** мониторинга —
    согласовать по режимам.
