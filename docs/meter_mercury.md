# Счётчик «Меркурий» — прогноз показаний

## Назначение

«Меркурий» — счётчик энергосбыта, установленный **последовательно с DDS238**
(дом). У него **нет интерфейса мониторинга**: снять показания автоматически
нельзя. Задача — оценивать (прогнозировать) его показания на **текущий момент
времени** с максимально возможной точностью.

## Источники данных для прогноза

1. **Ручные снятия** показаний «Меркурия» на конкретные моменты времени — хранятся
   в конфиге, раздел `mercury` (см. ниже).
2. **Статистика DDS238** по энергопотреблению/отдаче (посуточные тарифы
   «День»/«Ночь», накопленные `meter_import`/`meter_export`) — за период **от
   последней точки ручного снятия** до текущего момента.
3. **Незавершённый период** (текущие сутки/час) и **текущие показания DDS238**
   (`meter_import`, `meter_export` и посуточные тарифы) — чтобы довести прогноз до
   «сейчас».

Идея: так как счётчики включены последовательно, **приращения** энергии «Меркурия»
отслеживают приращения DDS238. Прогноз на момент `now`:

```
Mercury_est(now, tariff, dir) = Mercury_manual(last)                  // последняя ручная точка
                              + (DDS238_now(tariff, dir) − DDS238(last))  // приращение счётчика с того момента
```

где `tariff` ∈ {день, ночь}, `dir` ∈ {импорт, экспорт}. При необходимости вводится
калибровочный коэффициент (если связь не строго 1:1). Точная формула/учёт
незавершённого периода — при реализации отдельной задачей.

## Конфиг: раздел `mercury`

**Коллекция объектов** — ручные снятия показаний, по одному объекту на снятие
(хронологический порядок; последняя запись — самая свежая опорная точка).

```json
"mercury": [
  {
    "taken_at": "2026-10-05T23:00:00+03:00",
    "import_day": 33148,
    "import_night": 55418,
    "export_day": 31960,
    "export_night": 792
  }
]
```

| Поле | Значение |
|--|--|
| `taken_at` | дата и время снятия показаний, RFC3339 с часовым поясом (напр. `2026-10-05T23:00:00+03:00`, МСК). Может быть чуть впереди текущего момента — не критично |
| `import_day` | накопленный **импорт (день)**, kWh |
| `import_night` | накопленный **импорт (ночь)**, kWh |
| `export_day` | накопленный **экспорт (день)**, kWh |
| `export_night` | накопленный **экспорт (ночь)**, kWh |

Показания — «сырые» с лицевой панели счётчика (тариф «день»/«ночь» × импорт/экспорт).
Раздел публичный и не считается секретным (значения не искажаются в
`sunReceiver.sample.json`).

## Реализация (`mercury.go`)

Прогноз считается на каждый запрос `/api/current` (поле `mercury`) из последней
ручной точки `T0` (последний элемент раздела `mercury`) и живых показаний DDS238:

```
delta[field] = Σ финализированных дней [date(T0), date(now))   // из PG daily_tariffs
             + прирост сегодняшнего дня к now                    // meterTariffToday (Redis + границы PG)
             − прирост дня T0 к моменту T0                       // из границ 00:00/07:00/23:00 дня T0
forecast[field] = manual[last][field] + max(0, delta[field])
```

где `field` ∈ {import_day, import_night, export_day, export_night}. После
вычитания дня `T0` остаётся ровно энергия **после** `T0`. Прирост дня `T0`
считается точно, если `T0` попадает на тарифную границу (00:00/07:00/23:00);
иначе используется ближайшая предшествующая граница (погрешность — прирост после
неё). Если `T0` ещё в будущем (`now ≤ T0`) — прогноз равен ручным значениям.
Статическая часть кешируется (TTL 10 мин, `mercuryCacheTTL`).

Отображение: вложенная рамка **«Меркурий — прогноз»** в рамке DDS238 главной
страницы (2 столбца «Импорт»/«Экспорт» × 2 строки «День»/«Ночь»).
