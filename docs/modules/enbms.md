# Модуль EnBMS — мониторинг BMS Enjie (EMU110x) по BLE

Опрашивает BMS производства **Shanghai Enjie / N ENERGY** (бренд **EN BMS**;
модели EMU1101/1102/1103, 8S–16S LFP/NCM) по **Bluetooth Low Energy**. Читается
только блок **Battery** (CID2 `0x61`).

- Реализация: `enBms.go`, `enBms_client.go`, `enBms_poller.go`,
  `enBms_accumulator.go`, `enBms_store.go`.
- Протокол и живой срез: `/home/sasha/src/energybms` (`PROTOCOL.md`,
  `DEVICE_SNAPSHOT.md`).

## Конфигурация

Раздел **`enBms`** `sunReceiver.json`:

```json
"enBms": {
  "disabled": false,
  "devices": [
    { "name": "BMS BP00", "mac": "AA:BB:CC:DD:EE:00", "disabled": false }
  ]
}
```

- `disabled` (общий) — **обязательное** поле: `true` отключает опрос EnBMS целиком.
- `devices` — коллекция устройств. Каждый элемент: обязательный `disabled`;
  `mac` (обязателен для активного — BLE-подключение идёт по адресу) и/или
  необязательный `name` (отображаемое имя). Заводское BLE-имя (`BP00`) не
  уникально, поэтому ключ устройства — **MAC**.
- Отсутствие `disabled` у устройства — ошибка загрузки конфига.

## Транспорт BLE и протокол

| Роль | UUID |
|---|---|
| Сервис | `0000ff00-…` |
| Запись команд (host→BMS) | `0000ff02-…` |
| Уведомления/ответы (BMS→host) | `0000ff01-…` |

Кадр (big-endian), CRC-16/CCITT (полином `0x1021`, init 0) по `frame[1:len-3]`:

```
Запрос: 7E 10 ADR 46 CID2 LEN(2) INFO CHKSUM(2) 0D            (INFO с 7)
Ответ:  7E 14 ADR CID2 RTN LEN(2) INFO CHKSUM(2) 0D           (INFO с 7)
```

Полная длина = `10 + LENID` (`LENID = frame[5]<<8 | frame[6]`), CRC — по
`frame[1:len-3]`. Сборка — **строго по длине**, а не по `0x0D`: байт `0x0D`
встречается внутри payload. Ответ приходит несколькими notify-фрагментами —
склеиваются в буфере.

> Формат подтверждён живыми кадрами Battery/BasicInfo (CRC-16/CCITT). В
> `DEVICE_SNAPSHOT.md` полные кадры приведены без байта `RTN` — ориентироваться
> на живые (в тестах модуля зафиксирован реальный кадр).

Запрос Battery: `7E 10 00 46 61 00 01 00 <crc> 0D`.

### Payload Battery (106 Б)

`dataflag(u8) slaveNo(u8) batterynum(u8) cells[batterynum×u16, мВ] tempnum(u8)
temps[tempnum×u16, 0.1 K] current(s16, 0.01 А) totalV(u16, 0.01 В)
remaining(u16, 0.01 А·ч) customerp(u8) totalCap(u16, 0.01 А·ч) soc(u16, 0.1 %)
ratedCap(u16, 0.01 А·ч) cycles(u16) soh(u16, 0.1 %) portV(u16, 0.01 В) warnings…`

Мощность протоколом отдельно не отдаётся — считается `P = totalV × current`.

## Принципы работы (по образцу CE308 и ANT BMS)

- **Соединение постоянное**: пулер держит BLE-соединение с каждым устройством и
  не рвёт его между опросами; при обрыве переподключается с ограниченным
  бэкоффом (2…30 с). Транзиентный таймаут чтения ретраится (до 3 попыток) без
  разрыва связи; после 3 подряд неудачных опросов соединение переустанавливается.
- **Последовательный опрос**: устройства опрашиваются по одному; общий цикл — не
  чаще 1 раза в секунду (если суммарное чтение дольше — паузы нет).
- **Устойчивость BLE**: переиспользуются хелперы CE308 — управление питанием
  адаптера и перенацеливание tinygo на реальный `hciN`, сброс «залипшего»
  состояния BlueZ, discovery, если устройство не известно BlueZ.
- **Лимит BT-устройств**: суммарное число BLE-устройств (EnBMS + CE308) не должно
  превышать `enbmsMaxBTDevices` (5); иначе опрос EnBMS не запускается, в лог
  пишется ошибка.

## Хранение и усреднение

Схема — как у ANT BMS:

- Redis `sunreceiver:enbms:current` (HASH, поле = MAC) — текущий снимок;
- Redis `sunreceiver:enbms:series:<YYYY-MM>` (ZSET, 5-мин усреднённые точки,
  TTL 40 суток);
- PostgreSQL `sunreceiver.enbms_averages` (`name`=MAC, `ts`, `values` jsonb) —
  вся история; вставка с sample-count guard;
- неполный 5-минутный промежуток при остановке дописывается только в Redis.

Мгновенные поля (ток/мощность/SOC/ёмкости/напряжения ячеек/температуры)
усредняются за 5 минут; дискретные (число ячеек, циклы) берутся по последнему
снимку.

## Дашборд

EnBMS выводится на дашборд тем же API, что и ANT BMS, — с приведением к форме
`bmsDevice`/`bmsSeriesPoint` и полем `kind="enbms"`:

- `/api/bms` — «батарейки» на главной (блок `BMS (батареи)` включается, если
  настроен ANT BMS или EnBMS);
- `/api/bms/<MAC>` и `/api/bms/<MAC>/series` — страница деталей `/bms/<MAC>`
  (карточки, ячейки, температуры, графики 5-минутных средних из Redis+PG).

Чего в блоке Battery нет (состояния мощностных ключей/балансировки, счётчик
кадров), фронт скрывает по `kind`; отсутствующие у EnBMS поля остаются нулевыми.
