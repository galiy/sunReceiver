# Модуль веб-дашборда (`dashboard.go`)

HTTP-сервер — адрес из обязательного поля `dashboard_port` в `sunReceiver.json`
(`:<порт>`) — HTML-страницы + JSON API.
Сам дашборд **не пишет** ни в Redis, ни в PG — только чтение.

## API-эндпоинты

- `/api/current` — `HGETALL sunreceiver:current` (последнее состояние всех
  устройств). Go-сторона выделяет `total_power`/`total_pv` (сумма только
  fresh-устройств) и живые тарифы текущего дня (`meter_import_day`/...).
  Суммарные показатели дополнительно разбиваются по размещениям инверторов —
  полe `placement` в `sunReceiver.json` (по умолчанию «Дом»): список `placements`
  `[{name, power, pv}]`, одна пара плашек «активная + PV» на каждое размещение в
  рамке «Мощности инверторов». Порядок — по первому появлению размещения в конфиге.
  MPPT-контроллеры (КЭС) и МАП в эти суммы не входят.
- `/api/series` — временные ряды `ac_active_power` по инверторам, суммарный `total`,
  ряды МАП `map_grid_voltage`/`map_grid_power`/`map_battery_voltage`/`map_battery_power`,
  ряды счётчика `meter_*`. Применяется `downsampleSeries`.
- `/api/tariffs?from=&to=` — `pgStore.DailyTariffsRange` (финализированные дни).
- `/api/bms`, `/api/bms/<name>`, `/api/bms/<name>/series?from=&to=` — BMS (см.
  [../antbms.md](../antbms.md)).

Все series-API (`/api/series`, `/api/tariffs`, `/api/bms/<name>/series`) принимают
`from`/`to` в **RFC3339 (дата+время)**; поля «С/по» — `datetime-local`. Время суток
у `/api/tariffs` на выборку дней не влияет — важен календарный день в локальной зоне.

## Источник данных для рядов (`dashboardHandler.loadRange`)

Часть периода в последних 2 календарных сутках (от `recentCutoff`) читается из **Redis**
(полное разрешение ~10 с), более старая — из **PostgreSQL** (5-минутные средние).
Если `pg != nil` и период начинается раньше cutoff — из PG берётся `[start, cutoff)`,
из Redis — `[cutoff, end]`, результаты объединяются. При отключённом PG (пустой `db.pg`) —
только Redis в пределах окна удержания.

Ряды содержат **только реальные снимки** (`loadRange` ничего не достраивает).

## Усреднение длинных серий (`downsampleSeries`)

После сборки серии, если точек больше **1000** (`maxSeriesPoints`), диапазон
`[from, to]` делится на `n = min(1000, кол-во секунд диапазона)` равных периодов, и
все точки одного периода схлопываются в одну (среднее с округлением до 1 знака,
метка времени первой точки, пустые периоды пропускаются). Применяется только в
`apiSeries` (страница «Графики»); `/api/tariffs` и BMS-серии не затрагиваны.

## Страницы

- **`/`** — текущие параметры. КPI-плашки (суммарная мощность, PV),
  плашки МАП (напряжение/мощность сети и батареи, а также «Мощность дома» =
  `Σac(инверторы Дома) + grid_power + battery_power` — та же формула, что у ряда
  `house_power` на графике и у схемы анимации Дома), плашка счётчика (состав —
  `METER_PARAMS`; знаковые мощности окрашиваются: отрицательная = отдача в сеть),
  сводная таблица по инверторам/MPPT со строкой «Актуально», рамка «Потребление/
  Отдача за сегодня». Обновление каждую секунду.
  **Счётчик при устаревшем снэпшоте** (`MTR_STALE_MS` = 20 с): оперативные плашки
  (напряжение/ток/мощность/частота/коэффициент) выводят «—», а накопленные
  (потребление/отдача/тотал) продолжают показывать последнее значение.
- **`/charts`** — временные ряды (активная мощность по инверторам, суммарная,
  напряжение/мощность сети и батареи, счётчик, температуры). Обновление раз в
  минуту + кнопка принудительного обновления. Данные приходят ОДНИМ запросом
  `/api/series` за цикл — по нему строятся все графики страницы.
  **График температур** (`tempChart`): все температуры универсального контракта —
  инверторы (Deye/Sofar: «Корпус»/«Транзисторы») и МАП («Батарея»/«Тор»/
  «Транзисторы»), по линии на датчик. Ряды отдаёт `/api/series` (поле `temps`,
  `temperatureSeries`). Температуры в PG не усредняются (`accumulatorSkipTags`),
  поэтому за период старше окна удержания Redis строится только свежая часть.
  Кнопки-чипы линий, общий зум и синхронизация окна X — как у остальных графиков.
- **`/energy`** — посуточные и помесячные тарифы счётчика. Два независимых графика
  (бары на time-шкале, адаптер `chartjs-adapter-date-fns`).
- **`/bms/<name>`** — детали BMS (см. [../antbms.md](../antbms.md)).

## Зум и панорама (все страницы с графиками)

Только горизонтальные (`mode:'x'` в chartjs-plugin-zoom; mobile — через
`srTouchChart`). Старый вертикальный зум графика напряжений на `/charts` удалён
2026-09-16.

**Перезагрузка данных после зума/сдвига** (2026-09-16): по завершении жеста (десктоп
— колбэки `zoom.onZoomComplete` + `pan.onPanComplete`; touch — `onGestureComplete`)
ставится 300ms-debounce, после чего данные удаляются и грузятся заново под новое
X-окно, а поля «С/по» обновляются. На `/charts` и `/bms` окно X **общее для всех
графиков** (`srWindowChanged`/`bmsWindowChanged`); на `/energy` каждый график делает
**СВОЙ** запрос под своё окно (`energyWindowChanged`, per-chart debounce) —
независимо и без синхронизации. После зума+перезагрузки новое окно становится
**базовым** (`preserveZoom` + min/max вшиты в opts) — «Сброс зума» возвращает к нему,
а не к исходному периоду. Окно сохраняется и при ПЕРЕСТРОЙКЕ графиков
(`renderChart`/`bmsRender`/`renderEnergyChart`).

**Важно**: drag-панорама плагина требует загрузки **hammer.js** — скрипт
`hammerjs@2.0.8` грузится ПЕРЕД chartjs-plugin-zoom на всех страницах с графиками
(`/charts`, `/energy`, `/bms`); без него `window.Hammer` отсутствует и жесты
молча не инициализируются (работает только Ctrl+колесо — нативный wheel-слушатель).

**Курсор и хинты на `/bms`** (десктоп): при наведении на любой график вертикальная
чёрточка (`bmsCursor`) и штатные тултипы Chart.js показываются на **всех** графиках
страницы по общему срезу времени. Хинты выставляются программно через
`tooltip.setActiveElements` (`bmsSyncTooltips`): для каждого графика ищется ближайшая
по времени точка (`bmsNearestIndex`, бинарный поиск) и активными помечаются её видимые
линии; при уходе курсора хинты гаснут на всех графиках. На тачскрине не применяется
(там тултипы отключены, работает только зум/панорама).

## Аномалии отключившихся устройств

- На графиках: ряд содержит только реальные снимки. В хинте `drawCursorTooltip`
  ближайшая точка слева используется, только если ей не больше **20 минут**
  (`TOOLTIP_MAX_GAP`); в суммарном carry-forward `sumActive` вклад устройства тоже
  ограничен окном 20 минут (`staleWindow`).
- На главной: последний снимок оффлайн-инвертора живёт в Redis вечно (poller пишет
  только при успехе). Сигнал «оффлайн» — возраст снимка: `STALE_MS = 20 минут`
  (JS), Go-сторона `/api/current` — свой `staleCutoff` 20 мин. У stale-устройства в
  сводной таблице «Актуально» красное (`td.stale-time`), время недоступности второй
  строкой через `<br>`, данные ниже серийных номеров не выводятся (кроме
  «Выработка сегодня/всего» — серым `td.stale-keep`; серийные номера постоянны,
  остаются). Плашка «N инверторов онлайн» считает только fresh. `total_power`/
  `total_pv` суммируют только fresh — ночью плашка показывает «—», а не устаревшие
  значения заката. Строки мощностей («Активная»/«Реактивная») — сразу после
  серийных номеров, ярко-светло-зелёные (`tr.p-power`, `#66ff99`).

## Мобильная версия (тачскрин, ширина ≤900px)

Те же страницы, иная раскладка + touch-жесты. Общая часть — `mobileCommon`.
Раскладка — стекированные группы, плашки 2×N, нижняя фиксированная навигация
(Главная/Графики/Электроэнергия), сводная таблица — горизонтальный скролл с
закреплённой первой колонкой, увеличенные touch-цели. Жесты (только coarse-
устройства, `matchMedia('(pointer: coarse)')`): чипы легенды — tap = вкл/выкл,
long tap (≥450 мс) = только эта линия (`srBindChip`); графики — щипок = зум,
горизонтальный свайп = панорама, двойной тап = сброс зума (`srTouchChart`, canvas
`touch-action: pan-y`; после жеста `onGestureComplete` → перезагрузка данных под
новое окно). Хинт со значениями на touch отключён (`SR_COARSE||__srTouched`);
chartjs-plugin-zoom на touch отключён (`pan/wheel/pinch: enabled:false`), чтобы его
Hammer не перехватывал жесты. Вьюпорт `maximum-scale=1, user-scalable=no`.
**`<script>{{template "mjs"}}</script>` подключается ДО inline-скрипта страницы**
— скрипты синхронно вызывают `srTouchChart` при загрузке (иначе ReferenceError);
регрессионный тест — `dashboard_mobile_script_order_test.go`.
