# Уведомления в MAX (`notify.go`)

Модуль отправки событий мониторинга в мессенджер **MAX** через Bot API
(`platform-api2.max.ru`). Текущая версия следит только за МАП Титанатор
(батарея/сеть) — за его недоступностью и напряжением сети — и шлёт сообщения
при аварии и при восстановлении.

## Принцип работы

1. `maxClient` — лёгкий HTTP-клиент: `POST https://platform-api2.max.ru/messages`
   с заголовком `Authorization: <token>` (токен **только** в заголовке, не в query).
   Адресат — `user_id` (личный диалог) или `chat_id` (чат/канал). Лимит API —
   2 сообщения/сек на чат, 30 rps.
2. `mapTrack` — потокобезопасный трекер состояния МАП. Заполняется poll-функциями
   (`pollMAPAPI` для веб-API ПАК «Малина», ветка `kindMAP` в `pollDevice` для
   RS232/Modbus) — фиксирует последний успешный/неудачный опрос, причину ошибки
   и timestamp ответа веб-API.
3. `runNotifyMonitor` — фоновый цикл (каждые `notifyPollEvery` = 5 с): читает
   состояние МАП и через два `alertDetector` (недоступность / напряжение) шлёт
   сообщения с гистерезисом и дедупликацией.

> Подтверждение отправки/доставки: ответ `200` с объектом `message` (`mid`).
> `401` — неверный токен, `403` — нет доступа к получателю, `429` — лимит.

## Какие события отслеживаются

### 1. МАП недоступен
Конкретизируется причина в тексте сообщения:
- **`stale`** — веб-API ПАК «Малина» отдаёт сильно устаревшее время (поле
  `timestamp` ответа `read_json.php?device=map`), и оно **не изменяется**
  (зависший API);
- **`down`** — нет валидных данных дольше окна `map_undeclared`:
  - при источнике «веб-API» — недоступно/не отдаёт данные МАП (ошибка запроса);
  - при источнике «RS232/Modbus» — опрос не удался (нет данных от МАП).

### 2. Напряжение сети МАП отсутствует/ниже порога
Порог `grid_voltage_low` (по умолчанию **195 В**). Считается по напряжению сети
МАП (`grid_voltage`): если тега нет либо значение `< порога` либо `<= 0`.
Если опрашивается электросчётчик (раздел `meter`), в сообщение добавляется
справочное напряжение счётчика (`meter_voltage`).

### 3. Восстановление
По обоим событиям отправляется отдельное сообщение, когда состояние вернулось в
норму и продержалось окно стабильности.

## Гистерезис и стабильность

- **Авария** фиксируется после непрерывного удержания условия в течение
  `stable_window` (по умолчанию **30 с**).
- **Восстановление** — аналогично: состояние держится в норме `stable_window`,
  и только потом шлётся сообщение.
- **Дедупликация**: `alertDetector` отправляет сообщение один раз на переход, не
  повторяясь, пока состояние не сменится.
- Пока МАП недоступен, оценка напряжения приостанавливается (детектор
  сбрасывается) — аварию напряжения обработает ветка недоступности.

## Условие включения

Мониторинг запускается **только если включён опрос МАП в целом**: есть источник
МАП (RS232/Modbus — цель `kindMAP`, либо веб-API ПАК «Малина» — `mapAPI`).
Если опрос МАП выключен (`map.disabled=true` или нет источника), уведомления **не**
формируются, даже при настроенном разделе `notify`.

## Конфигурация (`sunReceiver.json` → `notify`)

```json
"notify": {
  "token": "CHANGE_ME",
  "user_id": "1234567890",
  "chat_id": "1234567890",
  "disabled": false,
  "stable_window_sec": 30,
  "map_undeclared_sec": 20,
  "grid_voltage_low": 195
}
```

| Поле | Обязательность | Описание |
|---|---|---|
| `token` | обязателен | токен бота MAX (в открытом виде, файл в git не выгружается) |
| `user_id` | да (или `chat_id`) | адресат — личный диалог |
| `chat_id` | да (или `user_id`) | адресат — чат/канал |
| `disabled` | опц. | `true` — раздел есть, но уведомления выключены |
| `stable_window_sec` | опц. | окно стабильности (дефолт 30) |
| `map_undeclared_sec` | опц. | окно недоступности МАП (дефолт 20) |
| `grid_voltage_low` | опц. | порог напряжения сети МАП, В (дефолт 195) |

Токен нужно брать из настроек бота на платформе MAX; `user_id`/`chat_id` — из
события `bot_started` (адресат запускает бота), т.к. вручную ID не узнать.

## Получение токена/адресата

- Токен — платформа MAX → **Чат-боты** → бот → **⋮** → **Настройки** → **Токен доступа**.
- `user_id` — `GET https://platform-api2.max.ru/updates` (long polling) при событии
  `bot_started` (пользователь открывает диалог с ботом `max.ru/<ник>`).

## Зависимости от TLS

Cert-цепочка `platform-api2.max.ru` подписана **Russian Trusted Sub CA** → корнем
**Russian Trusted Root CA** (Минцифры). На сервере должен быть установлен корневой
сертификат Минцифры в системный пул (`/usr/local/share/ca-certificates/` +
`update-ca-certificates`), иначе `Verify return code: 20` / `curl` без `-k` не пройдёт.
