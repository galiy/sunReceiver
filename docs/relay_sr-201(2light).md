# Сетевое реле SR-201 (2light) — лампы-индикаторы

Модуль управляет сетевым реле **SR-201 Network Relay** (Lee Software) с двумя
каналами путём отправки ASCII-команд по **UDP**. Аппаратно: реле 1 — **белая** лампа,
реле 2 — **красная** лампа. Каждая может быть в одном из трёх состояний —
**не горит / горит / мигает** (2 Гц), допустима любая их комбинация.

Состояниями ламп управляют другие модули проекта (Go-API) и жёстко предустановленные
алгоритмы-индикаторы (красная — отдача в сеть, белая — наличие напряжения сети).
Реализация — `relay_control.go`; включает контроллер, поддерживающий состояние по
UDP, и два фоновых цикла-индикатора.

## Устройство и доступ

| Параметр | Значение |
|---|---|
| Модель | SR-201 Network Relay (Lee Software), 2 канала |
| Протокол | ASCII-строки, без префиксов и разделителей |
| Порт управления (UDP, команды, без ответа) | **6723** (по умолчанию) |
| Порт TCP (чтение статуса `00`) | **6722** |
| Пароль / шифрование | нет — управление доступно только из локальной сети |
| IP устройства | задаётся в конфиге, раздел **`relay`** |

Протокол восстановлен из исходников поставки (Delphi `Unit1.pas`, VB `MainForm.frm`:
`sckTCP.RemotePort=6722`, `sckUDP.RemotePort=6723`) и подтверждён вживую.

## Протокол команд

Отправляется строка ASCII без завершающего символа. По TCP устройство отвечает
строкой из N символов `0`/`1` (позиция = номер реле).

| Команда | Действие |
|---|---|
| `00` | Запрос статуса (только TCP) → `"01…"`, `1` = вкл |
| `1N` | Реле N — **ВКЛ** |
| `2N` | Реле N — **ВЫКЛ** |
| `1X` / `2X` | Все реле вкл / выкл |
| Суффикс `:<сек>` | Авто-выключение через N секунд (1..65535; `0`/нет = держать) |
| Суффикс `*` | Jog (импульс) |
| Суффикс `K` | Имитация нажатия кнопки |

Реле 1 (`white`): `11` вкл, `21` выкл. Реле 2 (`red`): `12` вкл, `22` выкл.
Статус по TCP — например `10000000` (реле 1 вкл, остальные выкл).

## Конфигурация (раздел `relay`)

Управление настраивается целиком в `sunReceiver.json` (шаблон —
`sunReceiver.sample.json`; файл с реальными данными в git не попадает).
`disabled` — **ОБЯЗАТЕЛЬНОЕ** поле: `false` — модуль ламп включён; `true` — модуля
нет, управление/индикаторы не запускаются.

```json
{
  "relay": {
    "disabled": false,
    "ip": "192.168.0.34",
    "udp_port": 6723,
    "blink_hz": 2.0,
    "keepalive": "2s",
    "lamps": [
      { "name": "white", "relay": 1 },
      { "name": "red", "relay": 2 }
    ],
    "meter_stale_sec": 20,
    "map_stale_sec": 20,
    "meter_power_tag": "meter_active_power",
    "meter_voltage_tag": "meter_voltage",
    "map_grid_tag": "grid_voltage",
    "voltage_present_min": 0
  }
}
```

| Поле | Назначение | Дефолт |
|---|---|---|
| `disabled` | `false` — модуль включён, `true` — выключен | — (обязательно) |
| `ip` | IP устройства (обязателен при `disabled=false`) | — |
| `udp_port` | порт UDP команд | `6723` |
| `blink_hz` | частота мигания | `2.0` |
| `keepalive` | интервал повторной отправки steady-команды | `"2s"` |
| `lamps` | список ламп (`name`, номер `relay`) | белая(1), красная(2) |
| `meter_stale_sec` | окно свежести снэпшота счётчика | `20` |
| `map_stale_sec` | окно свежести снэпшота МАП | `20` |
| `meter_power_tag` | тег активной мощности счётчика | `meter_active_power` |
| `meter_voltage_tag` | тег напряжения счётчика | `meter_voltage` |
| `map_grid_tag` | тег напряжения на входе МАП | `grid_voltage` |
| `voltage_present_min` | порог «напряжение есть», В; `0` = `>0` | `0` |

## Как устроен модуль

Данные берутся **только** из Redis (`current-HASH`, поля — по IP устройства) и из
настроек; пулеры (инверторы, МАП, счётчик) о лампах ничего не знают — они лишь
пишут снимки. Анализ не встроен в пулеры: два фоновых цикла-индикатора читают Redis
и переключают лампы (`relay_control.go`).

### Поддержка состояния по UDP

UDP — без ответа, поэтому единственный владелец физических реле — фоновый цикл
`runRelayControl`, который непрерывно приводит реле к желаемым состояниям:

- **Мигание** — канал переключается вкл/выкл с частотой `blink_hz` (2 Гц = полупериод 250 мс).
- **Steady (on/off)** — команда повторно отправляется через `keepalive`-интервал
  (защита от потери UDP-пакета/сброса реле).

Другие модули задают **желаемое** состояние (`SetRelayLamp("white", lampOn)` /
`SetRelayLampByName`), не трогая вторую лампу; при том же состоянии — no-op.
Смена желаемого состояния логируется одной строкой; сами переключения при мигании
и повторные keepalive-отправки в лог не пишутся.

Желаемое состояние ламп сохраняется в Redis (`sunreceiver:relay`) — единый источник
для других модулей и дашборда.

### Дашборд / REST

- `GET /api/relay` — снимок состояния ламп (имя, канал, состояние).
- `POST /api/relay` — `{"name": <имя>, "state": "off|on|blink"}` — переключить.
  Эндпоинт регистрируется только при активном контроллере (`disabled=false`).

### Красная лампа — индикатор отдачи в сеть

Последовательный перебор (первое сработавшее условие решает):

1. Модуль счётчика отключён (`meter` выключен/не настроен) → **не горит**;
2. Счётчик недоступен (снэпшот отсутствует или старше `meter_stale_sec`) → **мигает**;
3. Мощность сети **положительная** (потребление из сети) → **не горит**;
4. Мощность сети **отрицательная** (отдача в сеть) → **горит**.

### Белая лампа — индикатор наличия напряжения сети

Последовательный перебор:

1. МАП недоступен или отключён (нет источника или снэпшот протух/отсутствует) → **не горит**;
2. Напряжение на входе МАП есть (`grid_voltage` выше порога) → **горит**;
3. Напряжения на входе МАП нет, но у счётчика оно есть и счётчик доступен
   (снэпшот свежий, выше порога) → **мигает**;
4. Напряжения на входе МАП нет и счётчик недоступен → **не горит**.

## Примечания по безопасности

Управление реле идёт по UDP/TCP открытым текстом без аутентификации — только в
локальной сети. Публичный IP дашборда при этом закрыт reverse-proxy (см.
`docs/https-setup.md`); данное реле наружу не публикуется.
