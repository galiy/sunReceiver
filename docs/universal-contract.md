# Универсальный контракт значений (`values`)

Документация на русский язык. Описывает **универсальный контракт** — набор тегов в секции
`values` файла JSON инвертора, которые имеют **одинаковые имена и одинаковые единицы
измерения** для обеих марок инверторов (Deye и Sofar).

Цель контракта: чтобы основные данные из устройств разных марок сохранялись в одинаковом
формате, в одинаковых единицах измерения и в тэгах с одинаковыми именами — чтобы единый
потребитель (граф, алерты, архив, экспорт) работал независимо от марки инвертора.

## Как читать

- Каждому тэгу соответствует физическая величина; **единица измерения зашита в суффикс
  имени** (напр. `_voltage` — вольты, `_current` — амперы, `_power` — ватты).
- Тэг, которого инвертор не отдаёт, в `values` **просто отсутствует** (не ставится `null`
  и не ставится `0`). Поэтому наличие тега — признак того, что у данной модели такое поле
  есть.
- Ключи `values` — в `snake_case`.
- Значения — числа (`float`/`int`), строки (`inverter_status`, `country`) или массивы строк
  (`fault_1..fault_5`).

### Структура файла JSON

Каждый инвертор — отдельный файл `data/<YYYY-MM-DD>/<IP>-<HHMMSS>.json`:

```jsonc
{
  "timestamp":    "2026-09-03T15:58:46+00:00",
  "device_sn":    "69c12409",           // серийный номер даталоггера (hex)
  "values":       { /* универсальный контракт — этот документ */ },
  "raw_registers":{ /* сырые именованные регистры — см. AGENTS.md */ }
}
```

`values` — контракт (ниже). `raw_registers` — сырые значения регистров под именами (не
объект контракта, хранит всё, включая недокументированные адреса под hex).

### Группы тэгов

| Группа | Теги |
|---|---|
| Общие (Deye + Sofar) | PV, AC, частота, фазы, энергия |
| Только Sofar | статус, фолты, страна, изоляция, диагностика |
| Только Deye | apparent/reactive-детали, sold/bought/load, uptime, PV3/4 |

## Общие теги (одинаковы у Deye и Sofar)

Общие тэги имеют **идентичное имя и идентичную единицу измерения** у обеих марок. Это
ядро контракта — на них строится кросс-марочный мониторинг.

| Тег | Ед. изм. | Тип | Описание | Sofar (рег., ratio) | Deye (рег., ratio) |
|---|---|---|---|---|---|
| `pv1_voltage` | V | float | Напряжение 1-й PV-цепи | 0x0006, ×0.1 | 0x6D, ×0.1 |
| `pv1_current` | A | float | Ток 1-й PV-цепи | 0x0007, ×0.01 | 0x6E, ×0.1 |
| `pv2_voltage` | V | float | Напряжение 2-й PV-цепи | 0x0008, ×0.1 | 0x6F, ×0.1 |
| `pv2_current` | A | float | Ток 2-й PV-цепи | 0x0009, ×0.01 | 0x70, ×0.1 |
| `pv1_power` | W | float | Мощность 1-й PV-цепи (DC) | 0x000A, ×10 | — |
| `pv2_power` | W | float | Мощность 2-й PV-цепи (DC) | 0x000B, ×10 | — |
| `ac_active_power` | W | float | Активная мощность на выходе AC | 0x000C, ×10 | 0x56/57 (32 bit), ×0.1 |
| `ac_reactive_power` | var | float | Реактивная мощность на выходе AC | 0x000D, ×0.01 kVar→×10 | 0x58, ×0.1 |
| `grid_frequency` | Hz | float | Частота сети | 0x000E, ×0.01 | 0x4F, ×0.01 |
| `l1_voltage` | V | float | Напряжение фазы L1 | 0x000F, ×0.1 | 0x49, ×0.1 |
| `l1_current` | A | float | Ток фазы L1 | 0x0010, ×0.01 | 0x4C, ×0.1 |
| `l2_voltage` | V | float | Напряжение фазы L2 | 0x0011, ×0.1 | 0x4A, ×0.1 |
| `l2_current` | A | float | Ток фазы L2 | 0x0012, ×0.01 | 0x4D, ×0.1 |
| `l3_voltage` | V | float | Напряжение фазы L3 | 0x0013, ×0.1 | 0x4B, ×0.1 |
| `l3_current` | A | float | Ток фазы L3 | 0x0014, ×0.01 | 0x4E, ×0.1 |
| `energy_today` | kWh | float | Выработка энергии за сегодня | 0x0019, ×0.01 | 0x3C, ×0.1 |
| `energy_total` | kWh | float | Суммарная выработка (lifetime) | 0x0015/16 (32 bit) | 0x3F/40 (32 bit), ×0.1 |

### Примечания к общим тегам

- **Согласование единиц энергии.** `energy_today`/`energy_total` у обеих марок — **кВт·ч**.
  Sofar 0x0019 хранит `×10 Wh` → в контракте `×0.01 kWh`; Sofar 0x0015/16 — 32-битное
  значение уже в кВт·ч; Deye 0x3C и 0x3F/40 хранят `×0.1 кВт·ч`.
- **Согласование `ac_reactive_power`.** У обеих марок — **вар (var)**. Sofar 0x000D
  хранит `×0.01 кВар` → в контракте `×10 var`; Deye 0x58 — `×0.1 var`.
- **Согласование `ac_active_power`.** Sofar 0x000C — 16 бит `×10 Вт`; Deye 0x56/57 —
  32-битное `×0.1 Вт`. У Deye есть ещё 16-битный 0x50 «operating power» — это **дубль**,
  в контракт **не** маппится (иначе конфликт ключей).
- **`pv1_power`/`pv2_power` — только Sofar.** Deye отдаёт напряжение/ток PV-цепей, но не
  готовую мощность цепи, поэтому `pv1_power`/`pv2_power` у Deye отсутствуют (для Deye DC
  мощность есть в `dc_total_power` — суммарно по всем цепям).
- **Фазы L2/L3.** На наших 1-фазных инверторах `l2_*` и `l3_*` обычно `0` — это нормально
  (регистрация есть, фазы нет).

## Теги только Sofar (K-TLX)

Эти поля даёт только Sofar. Для Deye их в `values` нет.

| Тег | Ед. изм. | Тип | Описание | Рег. (ratio) |
|---|---|---|---|---|
| `inverter_status` | — | string | Статус инвертора: `standby`, `self-checking`, `normal`, `fault`, `permanent`, иначе `unknown(N)` | 0x0000 |
| `fault_1` … `fault_5` | — | []string | Битовая маска аварий; массив имён сработавших битов, при отсутствии — `["no_error"]` | 0x0001–0x0005 |
| `country` | — | string | Страна/регион сети (стандарт): `Germany`, `Poland`, `UK-G59`, `UK-G83`, … иначе `unknown(N)` | 0x0027 |
| `time_today` | min | int | Время генерации за сегодня (минуты) | 0x001A |
| `time_total` | h | float | Суммарное время генерации (часы, 32 bit) | 0x0017/18 (32 bit) |
| `temperature_module` | °C | int | Температура PV-модуля | 0x001B |
| `temperature_inner` | °C | int | Внутренняя температура инвертора | 0x001C |
| `bus_voltage` | V | float | Напряжение DC-шины | 0x001D, ×0.1 |
| `pv1_sample_cpu_voltage` | V | float | Напряжение PV1 с slave-CPU (диагностика) | 0x001E, ×0.1 |
| `pv1_sample_cpu_current` | A | float | Ток PV1 с slave-CPU (диагностика) | 0x001F, ×0.01 |
| `countdown_time` | s | int | Тайм-аут обратного отсчёта | 0x0020 |
| `alert` | — | int | Код алерта | 0x0021 |
| `input_mode` | — | int | Режим PV-входа | 0x0022 |
| `comm_board_msg` | — | int | Сообщение/код комм-платы | 0x0023 |
| `insulation_pv1_to_ground` | Ом | int | Сопротивление изоляции PV1+ → земля | 0x0024 |
| `insulation_pv2_to_ground` | Ом | int | Сопротивление изоляции PV2+ → земля | 0x0025 |
| `insulation_pv_minus_to_ground` | Ом | int | Сопротивление изоляции PV− → земля | 0x0026 |

### Биты аварий (fault mask)

`fault_1..fault_5` — это пять регистров-масок. Каждый бит соответствует коду аварии:

| Бит | Код | Наименование |
|---|---|---|
| 1 | ID01 | grid_over_voltage (высокое напряжение сети) |
| 2 | ID02 | grid_under_voltage (низкое напряжение сети) |
| 4 | ID03 | grid_over_frequency (высокая частота сети) |
| 8 | ID04 | grid_under_frequency (низкая частота сети) |
| 16 | ID05 | pv_under_voltage (низкое напряжение PV) |
| 32 | ID06 | grid_low_voltage_ride_through (LVRT) |
| 256 | ID09 | pv_over_voltage (высокое напряжение PV) |
| 512 | ID10 | pv_current_unbalanced (дисбаланс тока PV) |
| 1024 | ID11 | pv_input_mode_wrong (неверный режим PV) |
| 2048 | ID12 | gfc_i_fault (утечка/GFCI) |
| 4096 | ID13 | phase_sequence (последовательность фаз) |
| 8192 | ID14 | boost_over_current (перегрузка по току буста) |
| 16384 | ID15 | ac_over_current (перегрузка по току AC) |
| 32768 | ID16 | grid_current_high (высокий ток сети) |

## Теги только Deye (string / grid-tie)

Эти поля даёт только Deye. Для Sofar их в `values` нет.

| Тег | Ед. изм. | Тип | Описание | Рег. (ratio) |
|---|---|---|---|---|
| `uptime` | min | float | Время работы с момента включения (минуты) | 0x3E |
| `dc_total_power` | W | float | Суммарная DC-мощность по всем PV-цепям | 0x52, ×0.1 |
| `ac_apparent_power` | W (ВА) | float | Полная (apparent) мощность AC | 0x54, ×0.1 |
| `grid_l12_voltage` | V | float | Напряжение между фазами L1–L2 | 0x46, ×0.1 |
| `grid_l23_voltage` | V | float | Напряжение между фазами L2–L3 | 0x47, ×0.1 |
| `grid_l31_voltage` | V | float | Напряжение между фазами L3–L1 | 0x48, ×0.1 |
| `temperature_radiator` | °C | float | Температура радиатора | 0x5A, ×0.1 − 100 |
| `temperature_igbt` | °C | float | Температура IGBT (часто не подключён → −100) | 0x5B, ×0.1 − 100 |
| `pv3_voltage` | V | float | Напряжение 3-й PV-цепи (на 2-цепных = 0) | 0x71, ×0.1 |
| `pv3_current` | A | float | Ток 3-й PV-цепи (на 2-цепных = 0) | 0x72, ×0.1 |
| `pv4_voltage` | V | float | Напряжение 4-й PV-цепи (на 2-цепных = 0) | 0x73, ×0.1 |
| `pv4_current` | A | float | Ток 4-й PV-цепи (на 2-цепных = 0) | 0x74, ×0.1 |
| `grid_power` | W | float | Активная мощность в/из сети (32 bit) | 0xCB/CC, ×1 |
| `load_power` | W | float | Мощность нагрузки (32 bit, signed) | 0xC6/C7, ×1 |
| `energy_sold_today` | kWh | float | Сдано в сеть за сегодня | 0xCD, ×0.01 |
| `energy_sold_total` | kWh | float | Сдано в сеть всего (32 bit) | 0xCE/CF, ×0.1 |
| `energy_bought_today` | kWh | float | Взято из сети за сегодня | 0xD0, ×0.01 |
| `energy_bought_total` | kWh | float | Взято из сети всего (32 bit) | 0xD1/D2, ×0.1 |
| `energy_load_today` | kWh | float | Потреблено нагрузкой за сегодня | 0xC8, ×0.01 |
| `energy_load_total` | kWh | float | Потреблено нагрузкой всего (32 bit) | 0xC9/CA, ×0.1 |

### Примечания к тегам Deye

- **`uptime` vs `time_today`.** Deye 0x3E — это **время работы с момента включения**
  (uptime), а **не** «время генерации за день». У Sofar аналогичного по смыслу поля нет,
  зато есть `time_today` (время генерации за день). Поэтому у Deye `time_today`
  **отсутствует**, а `uptime` имеет своё отдельное имя — чтобы не сливать разную
  семантику под одним тегом.
- **Температуры с офсетом −100.** `temperature_radiator`/`temperature_igbt` вычисляются как
  `raw × 0.1 − 100`. Если датчик не подключён (регистрация 0), значение = **−100** (так и
  есть у `temperature_igbt`).
- **`grid_power`/`load_power`/`energy_*`** — данные о взаимодействии с сетью и нагрузкой.
  На grid-tie без батареи значения «sold/bought» могут быть 0 (нет учёта обмена).

## Справочно: что НЕ попадает в контракт

- **`ac_apparent_power` у Sofar** — Sofar не отдаёт apparent-мощность, тег только у Deye.
- **`grid_l12/l23/l31_voltage` у Sofar** — межфазные напряжения Sofar в нашем диапазоне не
  маппит, тег только у Deye.
- **`inverter_status`/`fault_*`/`country`/изоляция у Deye** — Deye не отдаёт статус,
  битовые фолты, страну и изоляцию, этих тегов у него нет.
- **16-битный Deye 0x50 «operating power»** — дубль 32-битного `ac_active_power`, в
  контракт не маппится (только в `raw_registers`).
- **Недокументированные адреса Deye** (0x3D, 0x41–0x45, 0x51, 0x53, 0x55, 0x59, 0x5C–0x6C)
  — не входят в контракт; в `raw_registers` остаются под hex-адресом.
