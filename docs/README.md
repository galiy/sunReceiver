# sunReceiver

Go-приложение мониторинга домашней солнечной станции. Опрашивает инверторы
(Deye, Sofar) через их WiFi-даталоггеры (Solarman V5, TCP 8899), МАП Титанатор
(батарея/сеть, Modbus TCP), MPPT-контроллеры «КЭС» (веб-API ПАК «Малина») и
электросчётчик DDS238 (Modbus TCP), нормализует всё в единый контракт значений
и хранит в Redis (горячие данные, последние 2 календарных суток) + PostgreSQL
(вся история — 5-минутные усреднённые точки). Встроенный веб-дашборд.

## Что опрашивается

| Устройство | Протокол | Период | Данные |
|---|---|---|---|
| Инверторы Deye / Sofar | Solarman V5 (TCP 8899) | 10 с | PV, AC, энергия, частота, фазы, температуры |
| МАП Титанатор | Modbus TCP (502) | 1 с | напряжение/мощность сети и батареи |
| MPPT-контроллеры «КЭС» | веб-API read_json.php (HTTP) | 1 с | PV панели, заряд АКБ, выработка за сутки |
| Счётчик DDS238 | Modbus TCP (502) | 1 с | мгновенные значения + посуточные тарифы «День/Ночь» |

- **Инверторы** — раздел `invertors` в конфиге. Данные нормализуются в
  **универсальный контракт** `values` (одинаковые имена и единицы для Deye и
  Sofar). У каждого инвертора флаг `disabled` (обязательное поле): `true` —
  временно не опрашивается.
- **МАП** — раздел `map`. Напряжение/мощность сети и батареи для плашек и
  графиков дашборда.
- **MPPT** — раздел `mppt` (доступ к ПАК «Малина»). Состав контроллеров
  определяется **динамически** по ответу веб-API: контроллер появляется на
  дашборде, когда приходит в ответе, и исчезает, когда перестаёт отвечать.
- **Счётчик** — раздел `meter` (legacy: отдельный файл `dds238.json`).
  Мгновенные значения + посуточная статистика тарифов с добором пропущенных
  границ.

Инверторы опрашиваются раз в 10 секунд; МАП, MPPT и счётчик — в отдельном
1-секундном цикле `runMapPoll`/`runMeterPoll` (в Redis при этом сохраняется
одна точка на 10-секундное окно).

## МАП Титанатор (Modbus TCP)

Модуль автономного питания «Титанатор» (192.168.13.74:502, unit 1) —
агрегатор: к нему подключены АКБ и до 16 параллельных MPPT-контроллеров
Микроарт «КЭС» (`(C)mART`). Опрос — Modbus TCP (`modbusmap/`), блоки
holding-регистров:

| Блок | Регистры | Что это |
|---|---|---|
| `0x400..0x43F` | `_UAcc_med` 0x405/0x406 | напряжение АКБ (В), `(VH*256+VL)/10` |
| | `_INET`/`_UNET` 0x422/0x423 | ток/напряжение сети (0 В = сеть отсутствует) |
| `0x530` | `_I_Akb_MPPT` | суммарный ток заряда от MPPT |
| `0x580` | `_PNET_Sign_P` 0x587, `_PNET` 0x59A/0x59B, `_PLoad` 0x59E/0x59F | знак, мощность сети, мощность нагрузки |

В контракт `values` попадают: `grid_voltage`, `grid_power` (знак по
`_PNET_Sign_P`), `battery_voltage`, `battery_power` — это плашки «Сеть»/
«Батарея» вверху дашборда и графики «Напряжение сети, V» / «Мощность сети, W».
Конфиг — раздел `map` (`name`, `ip`, `unit`); ключ устройства в Redis/PG = IP МАП.

## MPPT-контроллеры «КЭС» (веб-API ПАК «Малина»)

MPPT-контроллеры **не регистрируются в конфиге** — состав определяется
динамически по ответу ПАК «Малина» (Raspberry Pi, 192.168.13.60): один
HTTP-запрос `read_json.php?device=mppt` (Basic-auth) в 1-сек цикле, массив
ответа — по объекту на каждый подключённый контроллер, индекс = слот.
Контроллер появляется на дашборде, когда приходит в ответе API, и исчезает,
когда перестаёт отвечать (ключ удаляется из `current`). Имя колонки —
`MPPT-<слот+1>`, ключ устройства — `IP_ПАК#mppt<слот>`, время снимка — поле
`timestamp` ответа API.

Пер-слотовый опрос MPPT через Modbus больше не используется — веб-API отдаёт
полные индивидуальные параметры каждого контроллера, которых нет в
Modbus-гейте МАП:

| Параметр API | Контракт `values` |
|---|---|
| `Vc_PV` / `Ic_PV` / `P_PV` | `pv1_voltage` / `pv1_current` / `pv1_power` — панели контроллера |
| `V_Bat` | `l1_voltage` — напряжение АКБ |
| `I_Ch` | `l1_current` — ток заряда |
| `P_Out` | `ac_active_power` — мощность на выходе контроллера |
| `Pwr_kW` + `Pwr_W`/1000 | `energy_today` — выработка за сутки (кВт·ч) |

Реализация — `mppt_api.go` (`mpptSite`, `FetchMPPTs`, `mapMPPTAPI`); конфиг
доступа — раздел `mppt` (`base_url`, `mppt_path`, `login`, `password` — пароль
в открытом виде, файл в git не выгружается). Документация API:
[`read_json.md`](read_json.md) (форматы `device=map|mppt|bat`) и
[`malina-web-api.md`](malina-web-api.md) (устройство ПАК, все PHP-эндпоинты).

## Счётчик DDS238 (мгновенные значения + посуточные тарифы)

Однофазный счётчик (Modbus TCP, 502, unit 1) опрашивается отдельным 1-сек
циклом `runMeterPoll` (`meter_poller.go`).

- **Мгновенные значения** — регистры 0..26: Total/Export/Import (32-бит, кВт·ч),
  напряжение, ток, активная/реактивная мощность, cos φ, частота. Теги `meter_*`
  пишутся в Redis/PG как все остальные устройства; на дашборде — отдельная
  плашка счётчика (не входит в сводную таблицу инверторов и в график
  `ac_active_power`).
- **Посуточные тарифы** — счётчик считает только суммарные Import/Export,
  разбивку «День/Ночь» делает программа: на каждой границе тарифной зоны
  (00:00, 07:00, 23:00 — константы `meterDayStartH`/`meterDayEndH`) захватывается
  показание, ближайшее к границе (±5 с), и пишется в
  `sunreceiver.daily_tariffs`. Когда у дня собрались все 4 граничных показания —
  день финализируется: `import_day`/`import_night`/`export_day`/`export_night`.
- **Добор пропущенных границ** (`meter_backfill.go`, `runMeterBackfill`): если
  опрос в момент границы был остановлен (перезапуск, отключение сети),
  фоновый процесс каждые 5 мин дописывает пропущенные границы, беря
  **ближайшее** к границе показание из зафиксированных в Redis снимков (поиск
  ±6 ч от границы). Границы старше окна удержания Redis (~2 суток) не
  восстанавливаются.
- **Живые тарифы текущего дня (рамка «Потребление/Отдача за сегодня»)** — помимо
  финализированных за прошлые дни, дашборд считает тарифные величины за
  текущие календарные сутки (00:00 → сейчас): потребление/отдача «День»/«Ночь»
  на базе актуальных показаний счётчика (Redis) и зафиксированных граничных
  показаний текущего дня из PG `daily_tariffs`. Поля: `meter_import_day` /
  `meter_import_night` / `meter_export_day` / `meter_export_night` в `/api/current`.

Конфиг — раздел `meter` в `sunReceiver.json` (`name`, `ip`, `port`, `unit`,
`first_reg`, `register_count`); отдельный файл `dds238.json` рядом с бинарником
поддерживается как legacy (шаблон `dds238.json.sample`). Полное описание —
[`dds238-meter.md`](dds238-meter.md).

## Конфигурация

Один файл **`sunReceiver.json`** рядом с бинарником (`os.Executable()`; при
`go run .` — fallback в CWD). Разделы: `invertors`, `map`, `mppt`, `db`,
`meter`. Файл приватный (пароль БД и MPPT — в открытом виде, в `.gitignore`);
публичный шаблон структуры — [`sunReceiver.sample.json`](../sunReceiver.sample.json).

| Раздел | Поля |
|---|---|
| `invertors[]` | `ip`, `name`, `type` (`deye`/`sofar`), `logger_sn`, `disabled` (обязательное) |
| `map` | `name`, `ip`, `unit` (Modbus, умолч. 1), `disabled` (обязательное: `false`=Modbus, `true`=веб-API ПАК «Малина», нужен раздел `mppt`) |
| `mppt` | `base_url`, `mppt_path`, `login`, `password` |
| `db` | `redis` (host:port), `pg` (DSN с паролем) |
| `meter` | `name`, `ip`, `port`, `unit`, `first_reg`, `register_count` |

## Хранение данных

- **Redis** — live-хранилище последних 2 календарных суток (полное разрешение ~10 с).
  HASH `sunreceiver:current` (последнее состояние всех устройств) + месячные
  ZSET `sunreceiver:series:<YYYY-MM>` (временной ряд). Запускается с persistence
  (RDB+AOF). При полностью пустом Redis данные восстанавливаются из PostgreSQL.
- **PostgreSQL** — вся история, но только в виде **усреднённых 5-минутных точек**
  (`sunreceiver.averages`). Фоновый процесс (`accumulator.go`) усредняет
  накопленные в Redis снимки и пишет в PG.
- **Тарифы счётчика** — `sunreceiver.daily_tariffs` (посуточно, «День/Ночь» ×
  потребление/отдача).

## Дашборд

Запускается в том же процессе (флаг `-dashboard`, умолч. `:8080`).

- **`/`** — текущие параметры: плашки (суммарная мощность, PV, сеть/батарея МАП),
  рамка «Потребление/Отдача за сегодня» (потребление/отдача × День/Ночь, kWh),
  электросчётчик, сводная таблица по инверторам/MPPT. Обновление каждую секунду.
- **`/charts`** — временные ряды (активная мощность по инверторам, суммарная,
  напряжение/мощность сети и батареи, счётчик) за выбранный период. Часть из
  Redis (2 суток), старая часть — из PG. Обновление раз в минуту.
- **`/energy`** — посуточные и помесячные тарифы счётчика.

## Сборка и запуск

```sh
go build -o sunReceiver .   # сборка
./sunReceiver               # запуск (persistent-процесс)
go run .                     # запуск из исходников (конфиг из CWD)
```

Флаги: `-redis <addr>` (умолч. из конфига), `-pg <dsn>` (пустая строка — выключить
PG), `-pg-restore-window <dur>` (окно реставрации Redis из PG), `-dashboard <addr>`,
`-file` (дополнительно писать JSON-файлы в `data/`).
