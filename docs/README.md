# sunReceiver

Go-приложение мониторинга домашней солнечной станции. Опрашивает инверторы
(Deye, Sofar) через их WiFi-даталоггеры (Solarman V5, TCP 8899), МАП Титанатор
(батарея/сеть, Modbus TCP), MPPT-контроллеры (веб-API ПАК «Малина») и
электросчётчик DDS238 (Modbus TCP), нормализует всё в единый контракт значений
и хранит в Redis (горячие данные, последние 2 календарных суток) + PostgreSQL
(вся история — 5-минутные усреднённые точки). Встроенный веб-дашборд.

## Что опрашивается

| Устройство | Протокол | Период | Данные |
|---|---|---|---|
| Инверторы Deye / Sofar | Solarman V5 (TCP 8899) | 10 с | PV, AC, энергия, частота, фазы, температуры |
| МАП Титанатор «КЭС» | Modbus TCP (502) | 1 с | напряжение/мощность сети и батареи |
| MPPT-контроллеры | веб-API read_json.php (HTTP) | 1 с | PV панели, заряд АКБ, выработка за сутки |
| Счётчик DDS238 | Modbus TCP (502) | 1 с | мгновенные значения + посуточные тарифы «День/Ночь» |

- **Инверторы** — в конфиге раздел `invertors`. Кросс-марочное потребление:
  данные нормализуются в **универсальный контракт** `values` (одинаковые имена и
  единицы для Deye и Sofar). У каждого инвертора есть флаг `disabled` (обязательный
  поле): `true` — временно не опрашивается.
- **МАП** — раздел `map`. Давит напряжение/мощность сети и батареи для плашек и
  графиков дашборда.
- **MPPT** — раздел `mppt`. Состав контроллеров определяется **динамически** по
  ответу веб-API ПАК «Малина»: контроллер появляется на дашборде, когда приходит
  в ответе, и исчезает, когда перестаёт отвечать.
- **Счётчик** — раздел `meter`. Мгновенные значения + посуточная статистика
  тарифов (потребление/отдача «День» 07:00–23:00, «Ночь» 23:00–07:00) с добором
  пропущенных границ.

## Конфигурация

Один файл **`sunReceiver.json`** рядом с бинарником (`os.Executable()`; при
`go run .` — fallback в CWD). Разделы: `invertors`, `map`, `mppt`, `db`, `meter`.
Файл приватный (пароль БД и MPPT — в открытом виде, в `.gitignore`); публичный
шаблон структуры — [`sunReceiver.sample.json`](../sunReceiver.sample.json).

| Раздел | Поля |
|---|---|
| `invertors[]` | `ip`, `name`, `type` (`deye`/`sofar`), `logger_sn`, `disabled` (обязательное) |
| `map` | `name`, `ip`, `unit` (Modbus, умолч. 1) |
| `mppt` | `base_url`, `mppt_path`, `login`, `password` |
| `db` | `redis` (host:port), `pg` (DSN с паролем) |
| `meter` | `name`, `ip`, `port`, `unit`, `first_reg`, `register_count` |

## Хранение данных

- **Redis** — live-хранилище последних 2 календарных суток (полное разрешение ~10 с).
  HASH `sunreceiver:current` (последнее состояние всех устройств) + месячные
  ZSET `sunreceiver:series:<YYYY-MM>` (временной ряд). Запускается с persistence
  (RDB+AOF). При полностью пустом Redis данные восстанавливаются из PostgreSQL.
- **PostgreSQL** — вся история, но только в виде **усреднённых 5-минутных точек**
  (`sunreceiver.averages`). Фоновый процесс (`accumulator.go`) каждый час
  усредняет накопленные в Redis снимки и пишет в PG.
- **Тарифы счётчика** — `sunreceiver.daily_tariffs` (посуточно, «День/Ночь» ×
  потребление/отдача).

## Дашборд

Запускается в том же процессе (флаг `-dashboard`, умолч. `:8080`).

- **`/`** — текущие параметры: плашки (суммарная мощность, PV, сеть/батарея МАП),
  электросчётчик, сводная таблица по инверторам. Обновление каждую секунду.
- **`/charts`** — временные ряды (активная мощность по инверторам, суммарная,
  напряжение/мощность сети и батареи, счётчик) за выбранный период. Часть из
  Redis (2 суток), старая часть — из PG. Обновление раз в минуту.
- **`/energy`** — посуточные и помесячные тарифы счётчика.

## Сборка и запуск

```sh
go build -o sunReceiver .   # сборка
./sunReceiver               # запуск (persistent-процесс)
go run .                     # запуск из исходников (конфиг из CWD)
```

Флаги: `-redis <addr>` (умолч. из конфига), `-pg <dsn>` (пустая строка — выключить
PG), `-pg-restore-window <dur>` (окно реставрации Redis из PG), `-dashboard <addr>`,
`-file` (дополнительно писать JSON-файлы в `data/`).
