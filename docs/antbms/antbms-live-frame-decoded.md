# ANT BMS 22PHB-TB-8-22S-240A — расшифровка живого кадра телеметрии

Результат анализа дампов UART (жёлтая линия A/485A) платы ANT BMS
22PHB-TB-8-22S-240A, снятых с USB-serial адаптера на ПАК «Малина».

## Итог: правильная скорость = 19200 бод, формат = классический ANT live-кадр

- **Скорость UART протокола — 19200 бод** (не 9600). На 9600 кадры
  "укорачиваются до 70 байт" и содержимое побито — это передискретизация
  (мы читаем вдвое быстрее), данные неверны.
- **На 19200** поток разбивается на **140-байтные кадры** с заголовком
  `AA 55 AA FF` каждые 140 байт. **Контрольная сумма кадра сходится** —
  железное доказательство корректности формата и скорости.
- Формат соответствует классическому ANT live-кадру `klotztech/VBMS`
  (см. `antbms-protocol-status-frame.md`).

## Демонстрация: два последовательных кадра (raw, 70 байт показано из 140)

9600 (побито, передискретизация 19200→9600):
```
0f ef 21 62 c2 e2 c2 c2 e2 c2 c2 a2 a2 22 a2 e2 c2 e2 e2 00.. 00 80 21 01 00 6a 42 43 05 4d 00 02 02 02 02 02 03 00..  48 e2 43 4d 0e 00 e0 e0 41 00 00 00 01
```
19200 (валидный live-кадр):
```
aa 55 aa ff 02 07 0c aa 0c a8 0c aa 0c a8 0c a9 0c aa 0c a9 0c a8 0c a6 0c a7 0c a7 0c a7 0c ab 0c a9 0c ab 0c ab 00 00...
```

## Расшифровка живого кадра 19200 (16S батарея)

Взят кадр по первому `AA 55 AA FF` (140 байт). Контрольная сумма **валидна**
(ожидаемая 5767 == кадровая 5767).

| Поле | offset | Значение | Расшифровка |

| Скорость | Размер/20с | Кадр | Вывод |
|----------|-----------|------|-------|
| 2400 | 1374 | мусор | неверно |

## Выводы для интеграции
1. Опрос BMS вести на **19200 бод, 8N1**.
2. Кадр — классический ANT live-кадр, парсер можно писать по
   `antbms-protocol-status-frame.md`.
3. Напряжения ячеек — offset 6 (у этой модели offset 4–5 заняты служебным
   `02 07`; в документации klotztech они на 4 — проверять по контрольной сумме).
   **Offset 6 подтверждён** библиотекой `imval/AntBMS.cpp`:
   `for (i = 6; i < (6 + CELL_COUNT*2); i+=2)` — тот же сдвиг, что и у нас.
4. Мощность/ток/SOC/температуры/ёмкости — все поля подтверждены живым кадром.
5. Дампы 9600 можно отбраковать; дампы 19200 (`dump_19200.bin`) — эталонные.

## Как заставить BMS вещать (активация дисплея)
BMS стартует вещание телеметрии только когда по RXD (зелёный провод) получает
keep-alive/запрос. Захвачено на зелёной линии (в покое, дисплей подключён):
**`5A 5A 00 00 01 01`** каждые **250 мс** на **19200**. Это read-запрос телеметрии
(см. `antbms-protocol-status-frame.md`/команды read). Подтверждено:
- `imval/AntBMS.cpp`: request-кадр `5A 5A 00 00 01 01`, begin(19200);
- `FastDeath/VBMS` AtyMain.java: формат 6-байт, checksum=(addr+data), 5A5A=read.

Чтобы «научить адаптер отправлять кадр инициализации в BMS»: адаптеру **слать**
в зелёную линию (RXD BMS) `5A 5A 00 00 01 01` на 19200 каждые ~250 мс. Для
передачи нужен TXD адаптера (зелёный провод) на зелёный BMS. Параллельно читать
жёлтую линию (TXD BMS) на 19200 — там пойдёт 140-байтный live-кадр. При попытке
активации допустимо переключать скорости (9600/19200), если BMS поведёт себя иначе.

## Не задействовано
- Протокол 2.x (`7E A1`, baud 19200, syssi/esphome-ant-bms) у этой платы НЕ
  наблюдается — плата вещает классический 140-байтный live-кадр. Возможно,
  отвечает и на запрос `7E A1` — отдельная гипотеза для проверки на живом
  устройстве, но для мониторинга достаточно пассивного потока.
