## Ключевые решения

1. **Модель кода**: BT-транспорт (соединение/поддержание/восстановление/ошибки)
   взят из модуля CE308 (`ce308_client.go`, `ce308_agent_linux.go`); опрос/хранение/
   усреднение — из модуля ANT BMS (`bms_poller.go`, `bms_accumulator.go`,
   `redis_store.go`, `pg_store.go`).
2. **Ключ устройства — MAC** (BLE-имя `BP00` не уникально). В Redis HASH
   `sunreceiver:enbms:current` поле = MAC; `name` — только отображение.
3. **Читаем только Battery** (CID2 `0x61`).
4. **Формат кадра (важно!)**. В `PROTOCOL.md` §3.1 таблица ошибочно указывает
   CID2 в байте 4 и LEN в байтах 5–6. По живым кадрам BasicInfo/ReadBMSParams
   (проверены CRC-16/CCITT) реальный кадр ОТВЕТА:
   `7E 14 ADR CID2 LEN(2) INFO(с байта 6) CHKSUM(2) 0D`, полная длина = `9 + LENID`,
   `LENID = frame[4]<<8 | frame[5]`. Запрос же: `7E 10 ADR 46 CID2 LEN(2) INFO(с 7) …`.
   Сборка — строго по длине (в payload встречается `0x0D`).
5. **Соединения постоянные**, переподключение с бэкоффом 2…30 с; ретрай таймаута
   чтения до 3 попыток; после 3 подряд неудач — реконнект.
6. **Последовательный опрос**, цикл ≤ 1/с.
7. **Лимит BT-устройств** `enbmsMaxBTDevices = 5` (EnBMS + CE308); при превышении
   опрос EnBMS не стартует. Значение подлежит уточнению на конкретном адаптере.
8. **Хранение**: Redis `sunreceiver:enbms:current` (HASH) + ряд
   `sunreceiver:enbms:series:<YYYY-MM>` (5-мин точки); PG `sunreceiver.enbms_averages`.
   Неполный промежуток при остановке — только в Redis.
