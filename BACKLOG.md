# Бэклог задач sunReceiver

Актуализирован 2026-10-16.

## МАП

1. **Подтвердить ячейку `_I2C_Err`.** Адрес `0x448` предположительный
   (`cmd/sunreceiver/map_errors.go`) — сверить с `map_errors.log` при первом реальном
   событии; при неверном адресе поправить.

## Модель устройства / идентификаторы

1. **Убрать рудимент `ip` у обособленных устройств (ce308, dds238, map).** После
   выделения в отдельные хранилища «IP» там — не адрес, а псевдоключ. Привести к
   образцу `dts017m`:
   - **ce308**: в `ce308Snapshot` убрать поле `ip` (ключ — `Name`).
   - **dds238 / map**: не использовать общий `deviceSnapshot.IP` как ключ — завести
     собственные снимки (`name`/`timestamp`/`values`) без `ip`; таблицы
     `dds238_averages`/`map_averages` — **без колонки `ip`**, PK `(name, ts)`
     (как `dts017m_averages`).
   - Перевести **чтение** на отдельные эндпоинты/ключи (по образцу `/api/dts017m/...`),
     а не подмешивание в общий `Current()/QuerySeries/Averages`.
   - `ip` оставить только сетевым сущностям: инверторы (реальный IP), MPPT
     (`mppt-<serial>`).
   - Затрагивает: `redis_store.go` (Current/QuerySeries), `pg_store.go` (Averages),
     `accumulator.go`, `dashboard.go` (main-current/анимация/графики/тарифы),
     `meter_*`, схемы PG. Делать с миграцией и чисткой (Python-скриптами, по правилу).

## Процесс

- **Миграции данных** — только отдельными скриптами на **Python**, запуск **с этого
  (dev) ПК** напрямую в БД (Redis/PG); в Go-приложении миграций нет (только схема).
- **Гигиена репозитория:** коммит/push — только по явному запросу, с проверкой на
  секреты; локальный `sunReceiver.json` синхронизировать с продовым.
