### 1. Не заносить в историю ошибки инверторов `no_data`

**Проблема:** инверторы без данных заносятся в историю как
`kind=inverter, code=no_data, msg="нет данных"` (в UI: «Нет данных от устройства ·
нет данных»), напр.:
```
2026-10-01 10:52:01  Инвертор  192.168.0.95  no_data  Нет данных от устройства · нет данных
```
Это шум: отсутствие данных — не авария устройства.

**Что сделать:**
1. В `runInverterPoll` (main.go) **не писать** в `device_errors` ошибки с
   `code == "no_data"` (оставить запись только для heartbeat-кодов и fault-регистров
   Sofar/Deye). Текущий код: блок `if !res.OK || !res.HasData` → убрать вызов
   `pg.InsertDeviceError` для случая «нет данных».
2. Почистить уже накопленную историю:
   ```sql
   DELETE FROM sunreceiver.device_errors
   WHERE kind = 'inverter' AND code = 'no_data';
   ```
   (выполнить на проде; пароль PG — в `sunReceiver.json`).
3. При необходимости — аналогично пересмотреть `no_data` для МАП/MPPT (решить
   отдельно), но запрос касается инверторов.

### 2. EnBMS: сигнальный хвост Battery (аварии) — раскладка найдена, калибруется (2026-10-01)

**Что сделано:**
- По `16S_V20_ADDR_EN.xml` (`teleSignal_Group`) восстановлена раскладка хвоста
  Battery (0x61): 16 байт protect ячеек + 6 байт protect температур + 2 (ток/напряжение)
  + 14 байт `Ext_Bit` (Warn/Protect) + 1 байт `Mode` = **39 байт**. Живой кадр
  (`DEVICE_SNAPSHOT.md`) подтверждает: INFO=106 Б, телеметрия=67 Б, хвост=39 Б.
- Включён декод (`parseEnBmsTail`): алармы из `Ext_Bit` + защиты ячеек/датчиков,
  маска балансировки (байты 7-8), режим. Локализация ru/en/zh добавлена.
- Включён **сырой лог** payload Battery (hex) в журнал с таймстампом снятия: при
  изменении хвоста и не реже 1 раза в 60 с (`enbmsRawLogInterval`). Формат:
  `enbms: RAW <name> (<mac>) ts=... tail=<hex 39Б> payload=<hex>`.

**Подтверждено на живом кадре (прод):** смещение `Ext_Bit` tail[24:38] даёт
**ложные аварии** на здоровой батарее (байты `01 03 08` в позициях 25-27 —
это статусы ключа/баланса/режима, а не Warn/Protect). Поэтому **и отображение
алармов EnBMS отключено** (`enbmsTailDecodeEnabled=false` — на дашборде плашек
нет), **и запись в историю** (`enbmsAlarmHistory=false`); ложные записи удалены.
Сырой лог хвоста ведётся. Дашборд/API: `alarms` отсутствует, `device_errors`
kind='enbms' = 0.

**Исправлено (реверс APK, 2026-10-01):** хвост Battery разобран по
`parseBody_Battery` (`BmsMsgUtil.dart` 0x3f3a18) + `toJson` (0x3def6c): warn-область
хвоста = смещения 0..23 (16 байт по ячейкам + 4 по температурам + env/power/charge
warn), а `01 03 08` на смещениях 25-27 — это статусы, не аварии. `parseEnBmsTail`
переписан на warn-область: на здоровом кадре алармов нет (проверено на проде).
Подробности — `energybms/PROTOCOL.md` §5.1.1, `REVERSE_ENGINEERING.md` §2.1.

**Осталось:** после первого реального warn-кадра включить историю
(`enbmsAlarmHistory=true`) и уточнить названия warn-полей (reserve vs battery).

### 3. Deye: аварии/fault-регистры — карта неизвестна

**Проблема:** в открытых источниках/репо нет адресов fault/warning-регистров Deye
string (в `deye-registers` и `solarman`-библиотеке их нет).

**Найдено (2026-10-01):** в `StephanJoubert/home_assistant_solarman` группа
**Alert** (rule 6, битфилд): 1-фазный hybrid — `0x0065..0x006A`, 3-фазный
`deye_sg04lp3` — `0x0229..0x022E`; для `deye_string` Alert **нет**, карты
bit→fault нет ни там, ни в `kbialek/deye-inverter-mqtt`.

**Сделано:** блок опроса Deye расширен до `0x3B..0x74` (читаем `Running Status`
`0x3B` и Alert `0x65..0x6A`); сырые значения логируются при изменении/раз в 10 мин
(`deye alert <ip>: status(0x3B)=N regs 0x65-0x6A = 0x...`). Базовая линия: все 5
инверторов `status=2`, Alert=0.

**Осталось:** при `status=3 (FAULT)` сопоставить биты Alert с авариями, завести
таблицу имён и включить decode появлений в `device_errors` (kind=device).
