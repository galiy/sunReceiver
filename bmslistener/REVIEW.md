1. ✅ **Корректность парсера кадра** (`bms_parse_frame`, `checksum_frame`): все смещения и интерпретации в границах 140 байт; чтений за `rxbuf` нет (парсер вызывается только при накопленном полном кадре). Мелкие замечания: температуры `rd16be` как unsigned (отрицательные °C дадут +65536−t → абсурдные +600°C, стоит sign-extend), нет валидации индекса `max_cell_idx` против `cell_count`.
2. ⚠️ **bms_feed — скрытый дефект (важно)**: при `rxlen == RX_BUFLEN` (`4096`) сбрасывается всё окно (`rxlen=0; pend=-1`), **теряя маркер и недочитанный кадр**, даже если тому хватило бы места со сдвигом. При 140-байтном кадре и буфере 4096 вероятность низка, но принципиальна при крупных пачках. Рекомендация: при переполнении сдвигать окно (memmove хвоста, сохранив `pend`).
3. ⚠️ **Probe/активация — потеря полкадра (важно)**: `dev_is_bms` накапливает rxbuf в локальной `t`, а при успехе возвращает только `fd`; накопленный частичный кадр теряется, новый слот `bms_reset` стартует с 0 (теряется последний неполный кадр). Не критично (данные придут снова), но лучше переносить `t` (rxbuf/rxlen/pend) в слот.
4. ⚠️ **publish_all — возможное усечение JSON (важно при многих устройствах)**: `BUFADD` молча усекает при переполнении `SHM_SIZE` (8192) и всё равно дописывает `}` и `]#EOF` → при 32 устройствах с 32 ячейками каждое возможен невалидный обрезанный JSON в shm. На 2 адаптерах не проблема, но риск есть. Рекомендация: проверять остаток места и сворачивать публикацию при нехватке.
5. ✅ **service_fds**: `r==0` (нет данных при VMIN=0) трактуется верно — порт не забывается, переходим к следующему. Реального EOF у tty нет; отваление узла уйдёт через `reap_silent` по времени. Ротация портов ок.
6. ✅ **reap_silent / main-loop**: однопоточность, гонок нет, утечек fd/памяти нет. Мелочь: при переводе часов назад `now - last_ok` может быть отрицательным → молчание не распознается (неважно в embedded).
7. ✅ **Безопасность/надёжность**: платформенная совместимость с gcc 4.9 (C99) ок; `cfmakeraw` не трогает `CREAD`, поэтому явное `|= CREAD` — правильно. Фильтр занятых портов по /proc есть, но проверка/открытие не атомарны (редкая гонка между конкурентами).
8. ⚠️ **Совместимость ТЗ**: сканирование каждые 30 с ✅, забывание молчащего 30 с ✅, публикация в shm 2018 своим ключом без конфликта ✅, C/gcc/systemd ✅. **Небольшое отклонение**: "непрерывный поток" подтверждается одним валидным кадром за окно probe, а не ≥2 подряд — возможна ложная маркировка при случайном совпадении CRC (мелочь).
9. 🔸 **Мелочи-чистка**: мёртвый `<sys/select.h>`/`READ_TIMEOUT_MS` (select больше не вызывается в service_fds); `bms_log` открывает файл на каждую строку (недорого на tmpfs, но антипаттерн); нет восстановления предыдущего termios при закрытии порта.

**Критических багов нет.** Основные риски: потеря кадра при переполнении буфера (#2), потеря полкадра при активации (#3), усечение JSON при многих устройствах (#4).
